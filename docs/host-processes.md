# 宿主命令的取消与进程生命周期

`processes.run_bounded()` 统一执行安装验收、代码任务 worker、固定质量检查和 Git 命令。不使用 shell；环境仍由各调用方的白名单构造。它管理进程生命周期，不提供 OS 沙箱、网络隔离或文件访问限制。

## 生命周期

- Windows：先启动 `-I -S` 的固定 Python 启动器，启动器等待管道门禁。父进程将它加入禁止 breakaway、带 `KILL_ON_JOB_CLOSE` 的 Job Object 后，才允许启动实际命令。Job 创建或绑定失败时拒绝继续执行，命令不提前运行。
- POSIX：使用独立 session/process group；结束时清理整个进程组。自行创建新 session 的进程可以逃离该组，因此这不是对恶意代码的隔离边界。
- 正常完成、非零退出、超时、输出超限、协作取消以及调用方异常都会清理所拥有的进程树。Windows 父进程崩溃时，最后一个 Job 句柄关闭也会终止其中的进程。
- 启动前、门禁释放前、运行轮询期间及结束后检查当前 `ExecutionBudget`。取消或 deadline 触发时，先清理进程，再传播原来的预算异常。

质量检查使用相同执行器，取消不再等待整个命令超时。输出保存在临时文件，按 stdout/stderr 合计限制保留字节；超限停止进程树。该限额是轮询终止条件和保留量限制，不是磁盘配额。输出可在两次检查间短暂超过阈值。

## 调用方限制

| 调用方 | 合计输出限制 |
| --- | --- |
| 安装验收、代码 worker | 默认 65536 字节 |
| 质量检查 | `max(65536, max_command_output_chars * 4)` 字节；返回模型前仍按字符裁剪 |
| Git 命令 | 8 MiB；达到限额时失败，不把截断内容当成完整 diff 或审批依据 |
| Git filter 配置探测 | 16000 字节，严格 UTF-8；失败关闭 |

stdout/stderr 可分开保留，机器可读 Git 输出不会混入诊断信息。失败或超时的 Git stdout 继续经过敏感内容过滤。

## 验证与剩余边界

`tests/test_processes.py` 使用实际父子进程验证正常退出、超时、输出超限和取消后子进程停止，并验证绑定失败不启动命令、取消前不启动、合计输出限制及质量检查取消。Windows 使用真实 Job Object；POSIX 分支需要在相应平台运行这些测试。

命令及模型生成代码仍在宿主用户权限下执行，未限制内存、文件访问或网络。真实模型评测继续要求显式费用确认；目前的离线模拟验收不产生模型 API 费用。
