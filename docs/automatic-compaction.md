# 自动上下文摘要

自动压缩在用户回合开始时检查完整历史：达到字符或本地估算 token 预算的配置比例，或新回合即将使旧历史超过轮数上限时，将较早完整轮次摘要为检查点。策略由 `compaction.AutoCompactionPolicy` 决定，经 `host_runtime.build_agent()` 应用于共享 Agent，不注册新工具或改变审批边界。

## 配置与费用

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `AUTO_COMPACT_ENABLED` | `false` | 显式开启自动摘要；开启后可能增加模型请求和费用 |
| `AUTO_COMPACT_TRIGGER_RATIO` | `0.8` | 字符或本地估算 token 达到预算的比例，范围 `(0, 1]` |
| `AUTO_COMPACT_KEEP_RECENT_ROUNDS` | `2` | 保留最近完整轮次的目标数量 |

实际保留数取配置值和 `MAX_ROUNDS - 2` 中较小者，为摘要检查点和新回合留出位置。`MAX_ROUNDS <= 2` 时沿用已有裁剪行为，不自动摘要。没有可进一步合并的旧完整轮次时不反复摘要同一个检查点。手动 `/compact` 保持可用。

摘要请求与工作请求、只读子任务和 SDK 重试使用同一个 [`TurnBudget`](turn-limits.md)。一次摘要准备最多 8 次逻辑摘要请求，也可能更早耗尽共享预算；请求超时仍受剩余 deadline 约束。`Agent.last_usage` 保持主工作循环成功逻辑响应的原有口径，`last_run_budget` 和回合共享元数据包含摘要请求；不能把前者当作完整账单。代码任务评测显式关闭自动摘要，保持固定评测协议。

## 准备与提交

1. 先验证当前输入本身能容纳在本地请求预算内；过大的新输入不会先消耗摘要请求。
2. 仅将较早历史作为引用数据交给无工具的摘要请求。摘要提示要求保留目标、约束、工具结果、验证结论和待办；较早历史的 thinking 与 Provider 私有重放字段不进入摘要正文。
3. 保留最近完整轮次中的工具调用、结果和 Provider 状态，校验调用/结果配对。过大的旧轮次仍沿用手动压缩的有标记有界摘要输入；摘要本身是有损信息，不能保证模型保留所有事实。
4. 验证摘要缩小历史，并且检查点、保留轮次、系统提示、工具定义与当前输入合计仍符合预算。候选只用于本回合请求选择，`Agent.messages` 继续表示已提交历史。
5. 完整工作回合成功时，一并提交候选和新消息。提交前比较原历史，拒绝覆盖准备期间改变的历史。摘要失败、工作失败、取消或流关闭均丢弃候选；已执行的文件操作继续按原有执行日志核对机制处理。

候选检查点使用独立的 automatic marker，不将运行时自动摘要描述成用户执行 `/compact`。检查点随现有版本化 JSON 会话保存和恢复，不依赖额外数据库。后续 hook 上下文和工具输出仍逐次进行原有请求预算检查；不会在未完成的工具链中间自动摘要。

## 验证

`tests/test_auto_compaction.py` 覆盖字符/token/轮数触发、默认关闭、最近工具轮次与私有重放状态保留、无私有字段的旧历史摘要、会话保存恢复、真实注册表工具往返、候选提交和失败/取消/关闭保护、过期历史拒绝、共享预算及四种宿主入口装配。全部使用离线模型，不代表摘要质量或真实模型任务成绩。
