# 任务文件检查点与威胁模型

## 目标与任务边界

任务文件检查点只为当前 Neil Agent 进程提供一次明确、可审查的撤销机会。一个任务定义为一次用户请求对应的完整 `Agent.stream_chat()` 回合，包括其中所有模型轮次和文件工具调用。

- 回合开始时打开临时任务边界，结束时才把有效修改加入历史。
- 成功、模型失败、hook 失败或用户取消都会关闭边界；已经完成的文件写入仍然可恢复。
- 同一路径在一个任务中反复编辑时，只保存第一次编辑前的正文和最后一次编辑后的哈希。
- 文件最终回到任务前正文时视为净零修改，不创建该路径的恢复记录。
- 文件工具在 Agent 回合之外被宿主直接调用时，每次成功写入仍形成一个兼容的单文件任务检查点。
- 每个最终检查点记录一个带时区的 UTC 创建时间，供只读历史排序；该时间不参与恢复身份绑定。

## 容量与失败语义

检查点容量是写操作的安全前置条件，而不是写入后的尽力补记。

| 边界 | 上限 | 超限行为 |
| --- | ---: | --- |
| 历史任务数 | 20 | 新任务完成后淘汰最旧任务 |
| 单任务路径数 | 50 | 下一次新路径写入前拒绝 |
| 单任务任务前正文 | 5,000,000 字符 | 下一次写入前拒绝 |
| 单任务任务后正文 | 5,000,000 字符 | 下一次写入前拒绝 |
| 单路径记录长度 | 1,000 字符 | 对应写入前拒绝 |
| 合并恢复预览 | 100,000 字符 | 保留所有路径/操作，按文件公平截断 diff |

旧检查点可以按历史总容量淘汰，但活动任务本身不能靠淘汰旧历史绕过单任务上限。容量拒绝不会修改目标文件；任务中更早且已经成功的写入仍会在任务结束后形成可恢复检查点。

## 恢复协议

`/rewind-task` 只处理最新的一个任务检查点，`/rewind-file` 是兼容别名。

1. 准备阶段按记录顺序解析全部路径，拒绝绝对路径、越界路径、符号链接、非普通文件、受保护目录和敏感文件。
2. 每个文件的当前 SHA-256 必须等于任务记录的最终哈希。
3. CLI 展示全部路径、恢复/删除动作和有界反向 diff，只有 `y` 或 `yes` 才继续。
4. 执行阶段先再次全量校验检查点 ID、路径集合、预览内容身份和全部文件哈希；任一变化都会在首个恢复写入前拒绝。
5. 每个文件修改前再做一次即时哈希检查。既有文件通过同目录临时文件、`fsync` 和 `os.replace` 恢复；任务中新建的文件被删除。
6. 普通执行错误发生后，已应用路径按反向顺序恢复到批准时的任务后正文。自动回滚成功时保留原检查点供重试；回滚不完整时明确要求检查工作区并使用 Git。
7. 全部路径成功后才消费检查点。

## 明确不提供的保证

这不是数据库事务，也不是 Git 的替代品。

- 多个独立路径之间不存在跨文件系统原子提交原语。进程终止、系统崩溃或断电可能发生在两个替换之间，导致部分恢复。
- 外部程序不遵守 Neil Agent 的检查点协议。多次哈希检查能发现常见并发修改，但无法消除检查与替换之间的所有竞态。
- 检查点不持久化；退出、崩溃或重启后会丢失。会话快照、导入导出和分支均不携带原文件正文。
- 只恢复 UTF-8 文件正文，不恢复目录、文件名变更、权限位、ACL、所有者、时间戳、扩展属性、硬链接关系或其他元数据。
- 原正文保存在当前 Python 进程内存中，可能包含项目敏感信息；它不会进入审计、运行时事件、会话、终端摘要或磁盘检查点。能够读取本进程内存的攻击者已经越过本能力的信任边界。

实时驾驶舱的 `F6` Time Machine 只读取当前进程内最多 20 个检查点，并立即投影为创建/修改文件数量和结果字符数。路径、哈希、原正文和结果正文不会进入长期 UI 状态；Time Machine 也没有恢复入口，实际恢复仍必须显式执行 `/rewind-task` 并经过上述预览与二次校验。

需要跨进程、跨重启、可审计或崩溃安全的恢复时，应在任务前创建 Git 提交、分支或 stash，并由用户审查最终 diff。
